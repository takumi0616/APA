いちいち試運転しなくていいです
また、現在動いているものの結果を見ても時間だけかかって正確な処理とは言えないです
改善してください
完璧なアルゴリズムでDocAligner後の改善処理を実装してください
きちんとどんな場合でも入力画像から4つの角を適切な位置で検出、用紙を認識させて次のステージに進ませてほしいです
特に絶対に改善してほしいのはDocAlignerが4つの角のうち、たまに2つの角を同じ場所だと誤認識している場合があります（この結果まるで3角形が用紙の形であるようになります）
2つの点が被った場合は適切に点の位置を論理処理で改善する処理を絶対に入れてください


```
2. DocAligner（用紙 polygon）の改善案（最重要）
2-1. まず “margin の上限 200px” が target では足りない可能性が高い
現状デフォルト：

--polygon-margin-ratio 0.12
--polygon-margin-max-px 200
たとえば紙の長辺が 3000px 程度なら、ratio 0.12 は本来 360px のマージンが必要ですが、max 200px で頭打ちになります。
DocAligner polygon が内側に 250〜400px ぐらいズレると、マーカー/QR が簡単に欠けます。

対応（まずは CLI だけで試せる・効果大）
--polygon-margin-max-px を 600〜1000 くらいに上げる
ratio も少し上げて候補を広げる（後述の評価で選ばせる）
例（精度優先の設定例）：

python APA/paper_pipeline_v17.py ^
  --target-limit -1 ^
  --polygon-margin-ratio 0.18 ^
  --polygon-margin-max-px 800 ^
  --docaligner-max-side 3200
ポイント：

margin を上げると「紙が小さく写る」副作用が出るので、rectify の最大辺も 2560→3200〜4096に上げて、角の解像度を落としにくくします。
2-2. expand_polygon の “画像境界 clip” が形を歪ませうる（精度面で地味に効く）
expand_polygon() は最後に

out[:, 0] = np.clip(out[:, 0], 0, w-1)
out[:, 1] = np.clip(out[:, 1], 0, h-1)
で角点を画像内に押し込めています。

margin を大きくすると、角点が外に出やすくなり、clip で四角形が潰れる → rectify がズレる、が起きます。

対応（精度最優先ならかなり効くことがある）
polygon を clip する代わりに、画像側を pad してから warp する方式にします。

degraded 画像を cv2.copyMakeBorder で周囲に padding（例: 800px）
polygon 座標を +pad だけ平行移動
margin を十分に取っても polygon が画像外に出ないようにする
rectify
こうすると、「margin を増やしたのに、端で clip されて意味がない」が減ります。

※ target の「端ギリギリ撮影」の救済に強いです。

2-3. DocAligner Multi の “探索順序” が精度最優先としては逆（重要）
_iter_docaligner_settings() でモデルの順序をこう並べ替えています：

model_pri = {"lcnet050":0,"lcnet100":1,"fastvit_t8":2,"fastvit_sa24":3}
models_u = sorted(models, key=...)
つまり lcnet100 → fastvit_t8 → fastvit_sa24 の順で試します。

しかし max_infer_runs=8 と max_polygon_candidates=4 により、

軽量モデルで候補が4つ取れた時点で打ち切り
高精度モデル fastvit_sa24 に到達しない
が起き得ます。
精度優先ならこれはかなり勿体ないです。

対応（コード変更だが効果が大きい可能性）
ユーザー指定モデル（デフォルト fastvit_sa24）を必ず最初に試す
その後に軽量モデルを補助として回す
例の方針：

models_u = [model0] + [m for m in models_u if m != model0]
2-4. docaligner_multi の候補評価が “target に最適化されていない”
detect_polygon_docaligner_multi() の候補評価は _quick_eval_form_scores_for_candidate() を使い、内部で decide_form_by_rotations() を回してスコア比較しています。

しかしここで使う formA_geom_cfg は None のままです（コメントにも「dataset が分からないので過剰緩和しない」）。

一方 process_one_case() の本番 decide では、target の場合：

surround_min_mean_gray を 150 に緩める
surround_max_ink_ratio を 0.08 に緩める
min_marker_area_page_ratio を 3.5e-5 に緩める
という target 用の緩和 cfg を適用しています。

つまり今は、

docaligner_multi の評価が “厳しすぎて” 正しい polygon を低評価
結果、変な polygon が残り、後段で no_detection
が起きる構造になっています（起きていても不思議ではない）。

対応（コード変更推奨・筋が良い）
detect_polygon_docaligner_multi() に source_dataset / formA_geom_cfg を渡し、
候補評価も本番と同じ cfg で回す
これで「polygon 選択」と「本番 decide」が同じ評価軸になり、選択ミスが減ります。

2-5. DocAligner 出力 quad の “角の微修正” を常用する
あなたのコードには既に良い部品があります：

_score_quad_by_edge_support
_refine_quad_corners_by_shi_tomasi
ただしこれは advanced fallback（輪郭ベース）側で主に使われています。

対応（精度優先ならおすすめ）
DocAligner の poly を得た後に、各角を Shi-Tomasi でスナップ（ただし探索窓は小さめに）
その前後で _score_quad_by_edge_support() が上がったら採用、下がったら戻す
これで「角が数十pxズレてマーカーが欠ける」みたいなケースに効きます。
```

4つの角を探す際に、たまに2つの角を同じ場所だと誤認識している場合があります
2つの点が被った場合は適切に点の位置を論理処理で改善する処理を入れてください

# プロンプト

@/APA/paper_pipeline_v17.py
上記のプログラムに以下の改善を行ってほしいです

改善1

現在はDocAligneでは検出ミスがいくつか発生しています
特に散見されるのが、3角形のような認識をしている場合や線のような認識をしている場合など、用紙の4つの頂点のうちどれかを認識できずにいます
そのような検出をされたまま進むと、当然他のstageでも検出などができません
以下の改善は一例なので、もっと効きそうな改善があれば積極的に取り入れてください
DocAlignerが十分な検証を経て、きちんと用紙と判定できるような4つの角を認識してから、次に進めるようにしたいです
```
1. DocAligner（紙検出）改善：最優先
ユーザーの所感どおり、ここが target のスコアを決めています。改善は大きく3系統あります。

1-A) DocAlignerを“1発勝負”にしない（複数候補→後段で選ぶ）
精度優先ならこれが最も効きます。

案：DocAlignerを複数条件で実行して polygon 候補を複数生成し、後段スコアで最良を採用

候補生成のバリエーション例
--docaligner-model: fastvit_sa24 / fastvit_t8 / lcnet100
--docaligner-type: heatmap / point
pad_px: 100 / 200 / 300
入力リサイズ：0.75x / 1.0x / 1.25x（polygonはスケールで戻す）
候補の選び方（重要）
候補ごとに rectify →（簡易）フォーム判定し、A/Bスコアが高いものを採用 （マーカー/QRは「紙の切れ」に極端に弱いので、ここが“評価関数”として優秀）
さらに攻めるなら rectify → XFeat（低解像・軽量）を1テンプレだけ当てて inliers を見る、でも良い
実装のポイント：process_one_case の stage2〜4 を「候補ループ」にして、最良候補だけ stage5〜へ進める。

これで DocAlignerが少しズレても「ズレない候補」が残り、target の form_unknown が減ります。

1-B) pad を増やす（targetで端ギリギリ撮影が多いなら特効）
detect_polygon_docaligner() は cb.pad(image_bgr, pad_px) を入れていますが、pad=100固定です。
targetで「紙が画像端に近い」ケースがあるなら、DocAlignerが角を外しやすいです。

提案：
PIPELINE_DEFAULTS["docaligner"]["pad_px"] = 200〜400
もしくは画像の短辺比で pad_px = int(min(h,w)*0.08) のように自動化
pad増加は計算量も増えますが、CPUでも「精度優先」なら最初にやる価値があります。

1-C) polygon拡張（expand_polygon）が“中心から放射状”なのが地味に危険
現状の expand_polygon() は「中心→各頂点方向」に押し出しています。
このやり方は、強い透視歪みや角の誤差があると「本当に欲しい外側方向」とズレます（四辺が平行移動されない）。

提案：辺法線方向にオフセットして、隣接辺の交点で新しい四角形を作る（いわゆる“polygon offset”）
これをやるだけで、「マーカー/QRがギリギリ切れる」系が減ることがあります
さらに精度優先なら：margin_px を単一値で決めずに
margin_px ∈ {0, 0.03*ref, 0.06*ref, 0.10*ref} を試して
フォーム判定スコアが最大のmarginを採用
（時間は増えるが、target成功率は上がりやすい）
```
