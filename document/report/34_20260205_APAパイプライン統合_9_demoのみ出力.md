# 34_20260205_APAパイプライン統合\_9_demoのみ出力

## 背景 / 目的

`paper_pipeline_v18.py` には要件外の処理（検証用の改悪系処理や、9_demo以外の中間画像保存など）が含まれており、
また実行に必要な実装が複数ファイルに分散していました。

今回の対応では、**`apa_input` の画像を順に処理し、9_demo 相当の出力画像だけを `apa_output` に保存する**
実用向けの最小ランナーを作成し、
重い実装（DocAligner / UVDoc / WeChat / XFeat / デモ画像生成）を **`APA_back.py` に統合**しました。

## 要件に対する対応

### 入力

- `./APA/apa_input` 配下の画像（ファイル名に依存せず、存在する画像を上から順に処理）

### テンプレート

- `./APA/apa_template/A`
- `./APA/apa_template/B`

### 出力

- **9_demo 相当の画像のみ**を `./APA/apa_output/run_.../` に保存

### ログ

- `./APA/apa_log/run_.../run.log`
- `./APA/apa_log/run_.../summary.csv`

ログには以下を出力します：

- 各入力が **フォームA/Bどちらと判定されたか**（`pred_form`）
- 各ステージの処理時間（doc/rectify/decide/uvdoc/bgdiv/match/warp など）
- 失敗した場合のステージ名と理由（`stage`, `error`）

## 実装方針（構成）

### `APA/APA.py`

- 薄いランチャー
- `APA_back.py` の `build_arg_parser()` と `run_apa_pipeline()` のみを import
- ファイル先頭に実行コマンド例をコメントとして記載

### `APA/APA_back.py`

- パイプライン本体を集約（DocAligner / UVDoc / WeChat / XFeat / demo9生成）
- **9_demo以外の画像保存処理は行わない**
- （精度に関わる）デフォルトハイパーパラメータは `PIPELINE_DEFAULTS` に保持し、変更しない方針

#### DocAligner 周りの改善

- DocAligner の polygon が **2点/重複点などで退化**しているケースを想定し、
  `paper_pipeline_v18` の思想に寄せて「4点（重複なし）」へ正規化する処理を追加。
- また、DocAligner multi の候補 polygon を **rectify→フォーム判定スコア**で再評価し、
  マーカー/QR が欠けて `no_detection` になりやすい polygon を避けるロジックを追加。
